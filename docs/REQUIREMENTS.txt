# Build a Production-Quality Classical Arabic Dictionary & AI App

## Objective

Build a complete, beautiful, fast, cross-platform mobile application for researching Classical Arabic, similar in functionality to https://ghareeb.app/.

The application should work on:

- iPhone 15 Pro (iOS)
- OnePlus 15 (Android)

Use React Native, Expo, and TypeScript.

The application must support BOTH:

1. **Cloud AI:** Cloudflare Workers AI using a powerful multilingual model.
2. **Local AI:** A downloaded GGUF model running entirely on the phone through llama.rn, without internet access or API costs.

Users must be able to switch between both modes from the app.

This is a serious application intended for real use, not a demo, mockup, or UI-only prototype.

Create an original identity and interface. Do not copy Ghareeb's branding, proprietary code, assets, or exact visual design.

Work autonomously. Research documentation, install compatible dependencies, implement features, run tests, and fix errors. Do not stop after scaffolding or creating mock screens.

Only request my involvement for credentials, device signing, licensing decisions, or other actions genuinely requiring user interaction.

## 4. Data ingestion and storage

Create a reproducible Python ingestion pipeline.

For each source:
1. Download or read the original source.
2. Parse its structure.
3. Preserve the original Arabic text.
4. Extract headings, roots, dictionary entries, and source metadata where available.
5. Segment long entries into searchable passages.
6. Normalize Arabic into separate search fields.
7. Generate stable entry and passage IDs.
8. Produce a SQLite database.
9. Build full-text and root-based indexes.
10. Validate imports and record errors.

Support:
- Arabic diacritic-insensitive searching
- Hamza/alif normalization in search fields
- Arabic root lookup
- Exact entry lookup
- Prefix and substring search where practical
- Arabic and English query text
- Book-specific filters

Preserve the original text exactly for display.

Do not confuse approximate stemming with authoritative root extraction.

For morphology, investigate MIT-licensed or otherwise compatible tools such as CAMeL Tools or PySarf. Verify compatibility and accuracy before selecting one.

If multiple roots are possible, display alternatives rather than confidently choosing an incorrect one.

Design the database so additional books can be added without rewriting the application.

Initially bundle a practical, genuinely searchable dataset with the app. For larger collections, support optional offline downloads.

## 5. AI architecture

Create a shared AI provider interface.

For example:

`AIProvider.generate(question, retrievedPassages, options)`

Implement two providers:
- CloudflareAIProvider
- LocalAIProvider

Both must consume the same retrieval results and return the same structured answer format.

Switching models should not require reloading the application or losing conversation history.

Each AI answer must be grounded in retrieved source passages.

### Retrieval pipeline

When a user asks a question:

1. Analyze the question and identify relevant Arabic words or roots.
2. Search the real dictionary database.
3. Retrieve relevant passages from multiple sources.
4. Rank the passages.
5. Select a compact, high-quality context.
6. Send that context to the selected AI provider.
7. Generate an explanation.
8. Validate cited source IDs.
9. Display the answer with clickable citations.

Start with deterministic lexical and root search.

Do not add a complicated embeddings infrastructure unless it demonstrably improves retrieval.

Later, support hybrid semantic retrieval if needed.

### Citation accuracy

This requirement is non-negotiable.

Each source passage must have a stable identifier.

The model should reference only the supplied passage IDs.

The application must validate all citations against the retrieval results.

Every clickable citation must open the actual source passage, with the relevant text highlighted.

Include book title, author, dictionary entry/root, and edition/page information where genuinely available.

Never invent quotations, source passages, page numbers, or reference IDs.

Clearly distinguish:
- Original Arabic source text
- AI translation
- AI interpretation

If the sources do not support an answer, the AI must say so.

## 6. Cloudflare AI implementation

Use Cloudflare Workers AI.

Default model:

`@cf/qwen/qwen3-30b-a3b-fp8`

Also support, where available on the free plan:

`@cf/google/gemma-4-26b-a4b-it`

Consult the current Cloudflare documentation:

https://developers.cloudflare.com/workers-ai/

Create a Cloudflare Worker that receives validated question/context requests and calls the model using an AI binding.

Do not expose Cloudflare API tokens or account credentials in the mobile application.

Store secrets server-side only.

Do not leave an unrestricted public inference endpoint that anyone can abuse.

For a personal-use prototype, implement a simple secure access mechanism with credentials configured by the user, not hardcoded into the app.

Structure the backend so real user authentication and per-user quotas can be added before public release.

Implement:
- Streaming when supported
- Request validation
- Input-size limits
- Output token limits
- Timeouts
- Network error handling
- Appropriate rate limits
- Quota-exceeded handling
- Model availability detection
- Clear retry controls

Keep requests efficient.

Use retrieved passages rather than entire books.

Target short-to-medium explanations by default.

The goal is to fit within Cloudflare's free Workers AI allocation of 10,000 neurons per day.

Do not enable paid usage automatically.

When the free quota is exceeded, display a friendly message and offer switching to Local AI.

Create a Wrangler configuration and a complete backend deployment README.

## 7. Local AI implementation

Use:

https://github.com/mybigday/llama.rn

Starting model:

https://huggingface.co/ggml-org/Qwen3-4B-GGUF

Prefer its Q4_K_M quantization, subject to actual device compatibility and benchmarking.

The model must run directly on the iPhone or Android device.

It must NOT require:
- A server
- An internet connection after download
- API keys
- AI credits
- Subscriptions

Implement a model manager.

Features:
- Download model from a trusted source
- Show total size before download
- Show download progress
- Handle interrupted downloads safely
- Verify model integrity using a known checksum
- Store the model in app-managed storage
- Load and unload the model
- Delete downloaded models
- Show available storage
- Warn when free memory/storage is insufficient
- Handle background/foreground transitions
- Avoid overlapping expensive inference requests

Use Metal acceleration on supported iOS devices.

Investigate suitable Android acceleration through llama.rn; use safe CPU fallback where GPU acceleration is unsupported or unstable.

Optimize context length, memory, and generation parameters for phone hardware.

Keep the downloaded model separate from the app bundle so users do not need to download several gigabytes during installation.

Offer automatic fallback to Local AI when cloud service is unavailable, but only if a model has been installed.

Make offline dictionary browsing and local AI genuinely work in airplane mode.

Do not provide a simulated local-AI mode or silently send local questions to a cloud API.

## 8. AI prompting and answer quality

Create a carefully designed system prompt for a Classical Arabic research assistant.

The assistant should:
- Understand Arabic and English questions
- Explain Classical Arabic accurately
- Translate source passages into natural English
- Explain roots, morphology, usage, and semantic differences
- Compare related Arabic words
- Cite the actual dictionary passages provided
- Differentiate literal translation from interpretation
- Preserve important linguistic nuances
- Admit uncertainty
- Avoid fabricating references or unsupported religious interpretations

Suggested answer structure:

**Word / root**

Arabic spelling, transliteration, root, and grammatical information when supported.

**Meaning**

Concise English explanation.

**Classical usage**

Details supported by the dictionaries.

**Related words**

Relevant forms and differences.

**Sources**

Clickable references to original passages.

For comparison questions, show a side-by-side or clearly separated explanation.

Do not make every answer unnecessarily long.

Support concise and detailed answer modes.
